Case study · 01 · Reputational and governance risk monitoring

FRIS fund manager risk monitoring

FRIS is an enterprise platform that monitors reputational and governance risk at 220 fund managers for due-diligence and investment teams. Every week it reads the news and regulatory releases about each manager, scores every development on a 20-point scale, and shows who is getting riskier, and why. An LLM judges each article, a multi-agent quality layer checks those judgements stage by stage, and deterministic rules turn them into a score an analyst can defend.

The problem

Early warning, buried
in thousands of articles.

Analysts who oversee fund managers on behalf of clients need to know early when a manager runs into trouble: redemptions gated, an investor class action, a regulator's probe. The signals are spread across thousands of articles a week, in many sources and several languages, and most of them are noise.

A language model can read that stream, but its judgements go wrong in patterns: a law-firm press release read as a lawsuit, a parent company's news pinned on its subsidiary, a reopening read as a resolution. Someone has to catch those errors every week, before clients see the result.

FRIS does that with agents instead of people, and still produces one number per entity that an analyst can defend: where it came from, which development set it, and what would bring it down.

What I built

Code sets the flow, models judge,
agents guard, rules score.

01 · DETERMINISTIC WORKFLOW

One command, eight stages, no model in charge

Collection, deduplication, clustering windows, scoring formulas and cooling rules are all code. The weekly run starts with one command, checks its own window and model access, and every stage exits with a status code.

  • Seven collectors: Google News, Yahoo Finance, SEC EDGAR, ASIC, FCA, ESMA, SFC
  • Cross-source deduplication, then 7-day semantic clustering into incidents
  • Parent-to-subsidiary propagation with rules for when a parent's news really applies
02 · MULTI-AGENT QUALITY LAYER

Agents that supervise the model

Built on LangGraph and organised like supervision on a construction site: the pipeline is the contractor, the agents are the inspectors. Each agent owns one stage and checks it before the next stage reads the results, when a correction still affects nothing downstream.

  • An inspector reads alongside the classifier in real time and can pause it when disagreement turns systematic
  • Classification, clustering, mitigation and scoring agents each own one gate; one field has exactly one writer
  • Agents coordinate through work items that must be closed within the run, not free-form chat
03 · CONSENSUS AND GUARDRAILS

The model proposes; code decides

A disputed verdict goes to three models from three different vendors: the producer explains its reasoning, an inspector reads the source blind, and a final reviewer rules. The ruling only lands if code-enforced guardrails pass.

  • Quotes must appear verbatim in the source or rulebook; headline-only articles are never escalated
  • Minimal moves only; each change is one transaction with a before-image and can be reverted
  • Scores stay pure arithmetic: highest category, cooling over time, credit for mitigations
04 · EXPLAINABLE BY CONSTRUCTION

Every rating explains itself

The category radar shows what is driving the score today, and the written analysis is generated from the scorer's own record, so every sentence traces back to a scored development. The same text goes into the PDF report for clients.

05 · BUILT FOR CLIENT WORK

Rankings, watchlists, reports

A multi-layer ranking across all entities, client watchlists, regional and asset-class filters, a top-movers view, PDF export, and sign-in so clients see only their own watchlist. A separate operations panel shows every run, every agent decision and its cost.

How it was built

An agent is only useful
if it can be held to account.

Code sets the flow, models judge

The model never outputs a final score or decides what runs next. Every score change traces back to a specific event or a specific rule.

Every alert needs a recipient

Agents don't raise warnings nobody reads. They issue work items to the agent downstream, which must accept or reject them, with a reason, in the same run.

One field, one writer

Each field has exactly one agent allowed to change it. Agents run in pipeline order and downstream agents never overturn upstream ones.

The model proposes; code decides

A ruling lands only if its quotes are found verbatim, the change is minimal and the score stays inside the category's range.

Agents earn their permissions

Every agent change is adjudicated independently. Accuracy over recent runs sets next week's edit budget, down to observe-only below 50%.

Never block production

The quality layer can fail without failing the weekly run: hard timeouts, a backup reviewer, and anything unfinished is dropped and logged.

Scope and limits
  • A monitoring signal for analysts, not investment advice or a credit rating.
  • Independent adjudication of agent changes is still confirmed by a person; the scoring agent only observes for now.
  • The recording runs the real frontend against a demo backend: every manager, client, headline and figure in it is fictional, and the employer's name is removed.
