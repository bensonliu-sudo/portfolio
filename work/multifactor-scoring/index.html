The problem

Pools built by hand,
hard to explain.

Research teams often build their candidate pools in spreadsheets: standardise a handful of factors, weight them, sort, take the top N. It works until someone asks why a stock is in the pool, or what changed since last week.

A changed weight leaves no trace, rounding differs between sheets, and outliers quietly dominate a score. The scoring itself is simple; making it exact, explainable and reproducible is the real work.

This tool takes the factor choices as given and does that part properly. Choosing factors, optimising weights and backtesting are deliberately out of scope.

What I built

A scoring layer that
shows its working.

01 · SCORING ENGINE

Exact, deterministic scores

Every factor is winsorised at k standard deviations, standardised, signed by its direction and weighted. The same data and configuration always produce the same pool, down to the last digit.

  • Optional industry-neutral standardisation
  • Missing values handled explicitly, never silently dropped
  • Bit-exact regression against an independent reference
02 · WEIGHT SANDBOX

Change a weight, see the consequences

Drag any weight and the pool re-scores instantly. The table shows which stocks entered or left the pool and how far each one moved, against the last official run.

  • Sandbox runs never overwrite the official result
  • Filter to entered, exited, up or down
  • One click to save a sandbox as the new official run
03 · CUTOFF EXPLANATION

Why this stock is in, or out

For any stock, a factor-by-factor breakdown: raw and clipped values, standardised score, weight and contribution, plus the distance to the rank-N cutoff and the factor that drives it.

04 · AUDIT TRAIL

Every run can be reproduced

Each run is stored with a snapshot of its configuration and a fingerprint of its input data, so any past pool can be traced and rebuilt. Results export to CSV.

How it was built

Built with AI,
verified like production.

Pin down the spec first

Every ambiguous rule (rounding, ties, missing values, clipping order) was written down and checked against an independent reference implementation before features were built on it.

Ship in gated packages

Engine, service, frontend and performance were separate packages. Each was frozen, hashed and reviewed before the next one started.

Independent adversarial review

A second AI re-computed results, injected faults and replayed real usage. Fifteen genuine errors were found this way; each one is documented with its fix.

Measure, don't assume

Performance claims come from a stress test at 5,000 stocks and 10 factors, timed end to end through the HTTP API.

Scope and limits
  • Scores one cross-section at a time; multi-period data and incremental updates are future work.
  • No factor research, weight optimisation or backtesting, by design.
  • Demo data is synthetic: 200 sample companies across 10 industries.
