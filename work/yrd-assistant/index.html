YRD Assistant

A desktop assistant that runs a financial publisher's daily report workflow: it finds the morning market commentary in Outlook, writes each section into the right WordPress draft, and drafts the confirmation email, while a person stays in charge of publishing.

The problem

A daily copy-paste job
that had to be perfect.

Every business day the publisher releases a bonds report and an equities report. The market commentary arrives by email in the morning, and someone has to copy four sections into two WordPress drafts, each under exactly the right heading, without disturbing the charts, tables and ads around them.

Then they confirm by email. It is repetitive, time-boxed, and the emails are messier than they look: reply threads carry yesterday's commentary, section order changes, headings run into the first sentence.

The goal was to automate the tedious part without taking the human out of the loop: nothing is ever published automatically.

What I built

Three layers, one
guided workflow.

01 · MAIL INTAKE

Find the right email, read it robustly

A Python intake step scans today's Outlook inbox newest first and recognises the commentary by its four section headings rather than a fixed intro sentence.

  • Ignores quoted reply threads, so old commentary never overrides today's
  • Works with any section order, inline headings and divider lines
  • Extracts the business date and retries while the mailbox is still starting up
02 · DRAFT UPDATER

Write into WordPress, never publish

A Node service finds the latest bonds and equities drafts through the WordPress REST API, matches each section heading in the post HTML and inserts the text beneath it.

  • Dry run first: validates every match before anything is written
  • Cleans empty filler markup so spacing matches the house style
  • Charts, tables and ad tags are left exactly as they were; posts stay in Draft
03 · DESKTOP ASSISTANT

One screen, five steps, a human in charge

An Electron app wraps the scripts in a guided flow: scan, review the dry run, generate drafts, publish manually in WordPress, then create the confirmation email as a reply-all draft for review.

  • Auto-scans during the morning window and retries every five minutes
  • Resettable run state, so a new operator can test without restarting anything
  • Browser fallback when the desktop shell is unavailable

How it was built

Real inputs are
messier than the spec.

Match on meaning, not on literals

Early versions keyed on a fixed intro sentence and exact heading names. Real emails broke both, so recognition moved to normalised section keys that tolerate variants and reordering.

Verify against real content

Spacing bugs only showed up in the live drafts' raw HTML, not in local templates. Fixes were checked against the real post content before release.

Keep a maintenance log

Every fault gets a symptom, root cause, fix and status. Eleven entries in three months show where the fragile edges are.

Automate the work, not the judgement

The tool prepares everything up to the publish button and drafts the follow-up email; deciding to publish and send stays with a person.

Scope and limits
  • Windows only: mail intake depends on the Outlook desktop client through COM.
  • An internal tool for one publishing workflow, not a general product.
  • The recording runs the real interface against a demo backend with synthetic commentary; publisher names and addresses are removed.
