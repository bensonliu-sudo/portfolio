## 6. CC 更新作品的日常流程

1. 先读本文及 README，检查本地工作区是否有用户或另一位维护者的未提交修改。遇到并行修改先协调，不执行覆盖式 reset、清理或强推。

3. 项目内容写清问题、实现、技术栈和成果；使用已核实的事实，截图和录屏应来自实际系统操作。概念图、合成数据和未完成的功能要明确标注。
4. 本地预览，核对桌面及手机宽度、导航、文字可读性、资源路径和代码/演示链接；检查 diff，避免把私人材料一起提交。
5. 提交明确的文件并推送 `main`。共享仓库有并行工作时，可先用分支/PR 整理变更，再合入生产分支。
6. 在 Vercel 对应部署中确认提交号及 `Ready`。随后打开正式域名检查本次改动；涉及域名时还要核对 `www` 跳转与 HTTPS。

## 9. 故障与回退

- **推送后没变化**：先核 Vercel 是否出现该提交、部署是否 Ready，再查是否推到 `main`、是否有浏览器缓存；不要第一步就改 DNS。
- **只有默认 Vercel 地址能访问**：查域名设置中的记录要求、Cloudflare 记录及证书状态。DNS/证书变更可能需要等待传播。
- **页面或资源报错**：查静态路径大小写、文件是否提交、Vercel 根目录/构建设置是否与当前实现一致。
- **需要回退**：先确定已验证的目标提交/部署。可在 Vercel 使用 Instant Rollback；源代码通常用 `git revert` 形成新的可追溯提交。回退部署后也要处理源分支，避免下一次推送把故障版本重新上线；不默认强推改写历史。
